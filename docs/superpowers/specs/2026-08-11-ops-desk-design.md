# miniftse ops desk: a FastAPI application

**Date:** 2026-08-11
**Status:** approved, pending implementation plan

## Purpose

`miniftse` produces its outputs as files — parquet levels and weights, markdown
one-pagers, JSON manifests, a chaos-drill table printed to a terminal. The
`2026-08-11-capacity-viz` spec addresses part of this with a static site that renders
the *outputs*. This spec addresses the other half: the parts of the platform that are
not outputs but **work** — the validation engine, the fault-injection drill, the
methodology assistant and its eval harness, the divisor audit trail, and the golden
master. None of those are visible from a chart, and all of them are what an index
research and operations function actually does all day.

This adds `desk/`, a small FastAPI application that puts five working surfaces on the
web: explain a day's index move from the audit trail, inject a fault and watch the
validation rules fire, ask the rulebook and see the evidence that the answer is
trustworthy, compare a rebuild against the pinned golden master, and browse the index
itself.

Non-goals: no authentication, no user accounts, no persistence of user input, no
recomputation of the index history on a request, no npm and no frontend build step, no
mobile-app packaging. This is a read-mostly window onto the library, not a new way to
run it.

**Relationship to `2026-08-11-capacity-viz`.** That spec's four tabs become this
application's fifth screen (§ Screen 5), server-rendered from the same exported JSON
rather than fetched by a separate static site. The `adv` threading work it specifies
(its Tasks 1–4) is a prerequisite and is not duplicated here. If the static site has
already shipped to GitHub Pages, keep it as a zero-dependency fallback and link to it
from the desk's footer; do not maintain two implementations of the same four tabs.

## Audience & hosting

Public, unauthenticated. The primary visitor is a hiring manager who has clicked a link
from a CV and will give the page perhaps ninety seconds. Two consequences drive the
entire architecture:

1. **First paint must be immediate.** A cold start that rebuilds an index is a failed
   demo. Everything historical is precomputed and committed; the app loads JSON and
   parquet at startup and serves from memory.
2. **It must work with no API key, no network egress and no spend.** `agents/llm.py`
   already provides `OfflineLlm`, a deterministic backend whose stated purpose is that
   "the whole AI layer is testable, benchmarkable and CI-runnable without keys, network
   or spend". The deployed app uses it. `AnthropicLlm` remains reachable behind an
   environment variable that production does not set.

Visitors are assumed hostile in the ordinary sense — they will send odd input. There is
very little input to send (see § Security), so this is not a threat model that needs
real hardening, but every user-supplied value is validated against a closed set.

## Architecture

```
src/miniftse/quality/rules.py     + ValidationContext.save() / .load()
src/miniftse/desk/
  __init__.py
  snapshot.py             builds desk/data/* from a reference build (CLI: desk-snapshot)
  services.py             pure functions: explain_day, run_drill, ask, compare_golden
  app.py                  FastAPI: lifespan, routes, error handlers
  templates/
    base.html             layout, nav, synthetic-data banner, HTMX + Chart.js includes
    day.html  chaos.html  ask.html  evals.html  draft.html
    reproducibility.html  index_tab.html
    partials/             HTMX fragment templates
  static/
    style.css  desk.js  capacity.js

desk/data/                committed, generated by `make desk-data`
  overview.json  constituents.json  capacity.json  risk_attribution.json
  days.parquet            per-date level/divisor/CA joined view for Screen 1
  chaos_baseline/         persisted ValidationContext (parquet + meta.json)
  chaos_precomputed.json  the full 12-fault drill result at the default seed
  golden_diff.json        pinned master vs current rebuild
  evals.json              EvalReport over the committed eval set

Dockerfile                + a `desk` stage / CMD for the web app
Makefile                  + `desk-data` and `desk-serve` targets
.github/workflows/ci.yml  + desk tests in the existing test job
```

`desk/` imports `miniftse` and calls it. **No index mathematics, no validation logic and
no retrieval logic lives in the web layer.** Every number on every page is produced by a
library call; the app's job is HTTP, HTML and bounded concurrency. This is a rule, not an
aspiration, and Task 14 adds a test that asserts `desk/` contains no arithmetic on index
values.

## Data pipeline

### The precompute / live split

| Screen | Precomputed at `make desk-data` | Computed per request |
|---|---|---|
| 1. Explain a day | `days.parquet`, divisor audit, review rows | join and format only |
| 2. Chaos console | `chaos_baseline/`, `chaos_precomputed.json` | **yes** — re-runs the 27 rules over the loaded context |
| 3. Ask the rulebook | chunked corpus, `evals.json` | **yes** — BM25 retrieval + `OfflineLlm` |
| 4. Reproducibility | `golden_diff.json` | no |
| 5. The index | the four capacity-viz JSON files | no |

Screens 2 and 3 are the only live paths, and both are cheap once their inputs are in
memory: the validation engine is 27 pure functions over pandas frames, and `Bm25Index`
is an in-process inverted index. Neither touches the network.

### The one real gap: `ValidationContext` cannot be persisted

`chaos_drill_cmd` (`src/miniftse/cli.py:95-158`) is the only existing way to obtain a
baseline `ValidationContext`, and it gets there by calling `build_index` over 200
securities and five years, then hand-assembling the context from
`universe._generated["prices"]`, `history.weights`, `result.calculator.engine.audit_frame()`
and six other pieces. That is tens of seconds of work and reaches into a private
attribute. It cannot run inside a web request, and copying its assembly logic into
`desk/` would put library internals in the web layer.

Instead: give `ValidationContext` (`src/miniftse/quality/rules.py:156-189`) `save(directory)`
and `load(directory)` methods. Its fields are seven optional DataFrames, one optional
Series, nine scalars and a `constituents` dict — parquet per frame, JSON for the rest.
`config` is an `IndexConfig` and is reconstructed by name rather than serialised.

This is a pure addition and it is independently useful: reproducing a validation run
from a past incident today requires rebuilding the index that produced it, which is
exactly the reproducibility problem `DECISIONS.md` takes seriously everywhere else.
Persisting the context is the same idea applied one layer up.

### `desk/snapshot.py`

One entry point, `build_snapshot(out_dir, spec)`, invoked by `miniftse desk-snapshot`
and by `make desk-data`. It runs a single reference `build_index`, then writes every
file listed in the tree above. It **fails fast** with a non-zero exit and a clear
message if any step produces nothing, rather than emitting a partial snapshot — the same
rule the capacity-viz spec applies to `export.py`. A broken snapshot must never be
committed.

Snapshot outputs are committed to the repo, like `artefacts/`. The deployed container
therefore needs no build step and no writable volume.

## Screens

Ordered by how much each differentiates the project, which is also the build order.

### Screen 1 — Explain a day (`/day`)

Pick a date. The page answers "why did the index level move, and what of that was the
market?" from data that already exists:

- Level and divisor, opening and closing, PR / GTR / NTR.
- Every divisor event on that date from `CorporateActionEngine.audit_frame()`
  (`corpactions/engine.py:413-429`): `event_type`, `security_id`, `divisor_before`,
  `divisor_after`, `divisor_change_pct`, `level_before`, `level_after`,
  **`continuity_error_bps`** and **`realised_return_bps`** — the last two being the
  whole point, since they separate the part of the move that was a real return from the
  part the divisor was supposed to absorb.
- The `_APPLY_ORDER` position of each event, so the sequencing rule is visible.
- If the date is a review effective date, the row from `IndexHistory.reviews`:
  additions, deletions, one-way turnover, `level_continuity_bps`.
- A plain-English narrative assembled from those facts.

Dates are chosen from a dropdown of the precomputed set, with the interesting ones
(largest divisor event, largest review turnover, largest continuity error) pinned to the
top as "notable days". Memo M2, *why our index level moved 30bp when nothing traded*,
is linked from the page and is the prose version of the same answer.

### Screen 2 — Chaos console (`/chaos`)

The 12 faults in `quality/faults.FAULTS` against the 27 rules in
`quality/checks.DEFAULT_RULES`.

The page loads showing `chaos_precomputed.json`: a table of fault → detected → detected
by → expected detector → severity → publication blocked, plus the coverage gaps that
`run_chaos_drill` returns as its second element. Each fault row expands to show its
`realism` string, because as `faults.py` puts it, "a drill against unrealistic faults
trains the wrong reflexes".

A **Run it** control re-runs the drill live against the loaded baseline context with a
user-chosen fault and seed, returning an HTMX fragment. Bounded: one fault at a time,
seed constrained to a small integer range, a `asyncio.Semaphore(2)` and a hard timeout.
The distinction between *expected detector* and *what actually fired* is the interesting
column and should be styled as such — a fault caught by the wrong rule is a coverage
finding, not a pass.

### Screen 3 — Ask the rulebook (`/ask`, `/evals`, `/draft`)

Three tabs over `agents/`.

**Ask** — `MethodologyAssistant` (`agents/rag.py:253-380`) over `ground_rules/` and
`memos/`. Render the answer, the `citations` list, the per-chunk `scores`, and the
`confidence` value with its derivation shown (top-hit score concentration). Critically,
render **abstention as a first-class outcome**: when `_scope_violation` fires or no
passage clears `min_score`, show the refusal prominently rather than as an error, with
the reason. Seed the page with three example questions, one of which is deliberately
out of scope so a visitor sees a refusal without having to think of one.

**Evals** — `evals.json`, produced by `run_evals` over the committed eval set.
Headline metrics (accuracy, citation precision, abstention accuracy, hallucination
rate), the `by_category` breakdown, and **the failing cases listed by name with
`CaseResult.explain()`**. Showing the failures is the point of the screen; a
scoreboard that only shows the wins is marketing.

**Draft** — `ClientResponseDrafter` plus `NumberGuard` (`agents/drafter.py:102-135`).
Pick a canned client question, see the `FactPack` (every number, its value, its source),
the drafted response, and the `GuardResult` — including a toggle that injects an
unverified number into the draft so a visitor watches the guard reject it. This is the
concrete demonstration of `llm.py`'s first hard rule: no number in a client-facing
output originates from a language model.

### Screen 4 — Reproducibility (`/reproducibility`)

`golden_diff.json`: the pinned master's `git_sha`, `created_at`, `content_hash` and
tolerance, against a current rebuild, rendered from `ComparisonResult` —
`n_compared`, `max_diff_bps`, `first_divergence`, `divergent_dates`, `column_diffs`.

Below it, a written incident: **the September 2024 constituent divergence**. A rebuild
on Linux produces 153 constituents at the 2024-09-20 review where the master pinned on
Windows has 154; the divisor absorbs it (`level_continuity_bps` is 0.0, so the rebase
maths is correct) but the two histories are thereafter different indices, diverging up
to 0.74bp on the divisor. Root cause: `universe/banding.py:81` computes the cumulative
percentile with `np.cumsum`, whose last bits are not stable across BLAS
implementations, and line 112 compares it to the band cutoff with a bare `<=` carrying
no tolerance. A security sitting on the cut lands on opposite sides on the two
platforms.

The page states the conclusion plainly: **a rule whose outcome depends on
floating-point summation order is not a rule.** The fix — deterministic summation,
quantisation to a documented precision before comparison, and the tie-break written into
the ground rules — belongs in `DECISIONS.md` and the ground rules, not only in code.

This screen is deliberately a published defect. It is the strongest single artefact on
the site.

### Screen 5 — The index (`/index`)

The `2026-08-11-capacity-viz` content: overview stat tiles and the PR/GTR/NTR history
chart, the sortable constituents table, the six-scheme trade-off table with the
client-side fund-size slider, and the parsed risk and attribution one-pagers. Rendered
from the same four JSON files that spec defines, served by FastAPI instead of fetched
statically. `capacity.js` is unchanged.

## Backend

FastAPI with Jinja2 templates and HTMX. `jinja2` is already a dependency
(`pyproject.toml`); `fastapi`, `uvicorn[standard]` and `python-multipart` are added.
HTMX and Chart.js load from a pinned CDN `<script>` tag. **No npm, no bundler, no
build step** — the same constraint the capacity-viz spec adopted, for the same reason.

Server-rendered HTML with HTMX fragments rather than a JSON API plus a client
framework: the interactive surface is three forms and a slider, and a SPA would be more
machinery than the problem has.

Routes:

```
GET  /                      redirect to /day
GET  /day?date=YYYY-MM-DD   Screen 1
GET  /chaos                 Screen 2, precomputed table
POST /chaos/run             HTMX fragment, live drill (fault_id, seed)
GET  /ask                   Screen 3 tab 1
POST /ask/query             HTMX fragment, one question
GET  /evals                 Screen 3 tab 2
GET  /draft                 Screen 3 tab 3
POST /draft/render          HTMX fragment (question_id, inject_bad_number: bool)
GET  /reproducibility       Screen 4
GET  /index                 Screen 5
GET  /healthz               liveness, returns snapshot git_sha and load time
```

Application state is loaded once in a `lifespan` context manager into a frozen
`DeskState` dataclass and read-only thereafter. Startup budget: **under two seconds**,
enforced by a test.

## Deployment

Hugging Face Spaces, Docker SDK, from the existing `Dockerfile` with a `CMD` running
`uvicorn miniftse.desk.app:app --host 0.0.0.0 --port 7860`. Chosen over Render's free
tier because Render sleeps and a cold start loses the visitor; the free-tier trade-off is
the whole hosting decision. Fly.io with a machine held warm is the documented
alternative.

The container needs no secrets. `MINIFTSE_LLM=offline` is the default and the deployed
value; setting `MINIFTSE_LLM=anthropic` plus `ANTHROPIC_API_KEY` switches to
`CachingLlm(AnthropicLlm(...))` for local use only.

## Security

Read-only by construction: no database, no writes outside `tempfile`, no user-supplied
code, no file paths accepted from a request. Every user input is validated against a
closed set before it reaches a library call —

- `date` must be a member of the precomputed date index; otherwise 400.
- `fault_id` must be in `{f.fault_id for f in FAULTS}`; otherwise 400.
- `seed` is an `int` bounded to `0..999_999`.
- `question` is capped at 500 characters and is only ever tokenised by
  `agents.rag.tokenise` and matched against an in-memory index.
- `question_id` for the draft tab is an index into a hard-coded list.

A simple per-IP token bucket (60 requests/minute) on the three POST routes, in-process,
no Redis. Templates use Jinja2 autoescaping.

## Error handling & edge cases

- Missing or malformed snapshot at startup: **fail loudly and refuse to start**, with a
  message naming the missing file and telling the operator to run `make desk-data`. A
  desk serving half its screens is worse than one that does not start.
- A live drill that times out returns the precomputed result for that fault with a
  visible "showing precomputed result" badge, not an error page.
- An empty retrieval is not an error — it is an abstention, and it renders as one.
- A date with no divisor events renders the "nothing structural happened; the whole move
  was the market" case explicitly. That case is the one the screen exists to explain.
- 404 and 500 handlers render inside the site layout so a visitor never sees a raw
  traceback.

## Testing

`tests/test_desk.py`, using `fastapi.testclient.TestClient` against a snapshot built
from a small spec (100 securities, one year) in a `tmp_path` fixture:

- `ValidationContext.save`/`load` round-trips every field, including `None` frames and
  the `weights` Series (Task 1 — this one gets real unit tests, not smoke tests).
- `build_snapshot` writes every expected file and exits non-zero when an input is
  missing.
- Each GET route returns 200 and its distinguishing content.
- Each POST route returns 200 for valid input and 400 for out-of-set input.
- The live drill and the precomputed entry for the same fault and seed agree.
- Startup completes within the two-second budget.
- `desk/` contains no index arithmetic (grep-style assertion over the module source).

The existing CI `test` job picks these up with no workflow change beyond adding
`fastapi` to the dev environment. Frontend rendering is verified manually in a browser.
